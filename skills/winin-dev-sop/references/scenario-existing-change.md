# 修改现有功能

## 适用条件

修改已有页面、接口、校验、计算、流程、状态或业务行为。若需求没有改变任何可观察行为，考虑“简单修改”或工程重构。

```mermaid
flowchart LR
    A["固定当前正确行为"] --> B["找出变更点和影响调用方"]
    B --> C["写明新旧规则差异"]
    C --> D["设计新行为与回归测试"]
    D --> E["人工确认方案"]
    E --> F["最小修改"]
    F --> G["验证新旧边界"]
```

## 执行动作

1. 用现有测试、特征测试或可重复脚本固定当前正确行为。
2. 用“旧行为—新行为—不变化内容”描述需求，避免把所有旧逻辑一起重写。
3. 查找入口、调用方、公共对象、数据和历史兼容影响。
4. 测试覆盖新规则、旧规则中仍应保留的部分、边界值、异常和权限。
5. 方案和测试设计经开发人员确认后再编码。

## 示例

任务：固定分隔符配置改为同一层级字段使用对应层级的分隔符。

AI 应先确认层级定义、配置结构、旧配置兼容方式和示例 `A:100;B:30,20;C:TEST` 的解析结果，再检查公共配置对象和调用方。若发现必须修改公共对象，应暂停并请求范围确认。

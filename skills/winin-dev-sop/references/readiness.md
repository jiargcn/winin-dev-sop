# 开工检查

## 检查顺序

1. 确认任务目标、范围外内容和可观察的验收标准。
2. 确认源码目录、当前分支、基线提交和已有未提交修改。
3. 定向查找相关页面、接口、服务、数据表、配置和测试。
4. 根据任务内容判断是否需要下表中的资料。
5. 将资料标记为“已取得”“缺失”“不适用”或“人工豁免”。只有必要资料缺失才阻断。

## 按条件要求资料

| 条件 | 需要的资料 | 不满足时的动作 |
| --- | --- | --- |
| 页面或交互变化 | 原型、截图或清晰的交互描述 | 无法确定视觉或交互结果时请求补充 |
| 接口变化 | 当前契约、调用方、请求响应样例、兼容要求 | 不允许根据单一实现猜测公共契约 |
| 数据库变化 | 目标版本 DDL、迁移记录、索引和约束 | 资料未对齐目标环境时停止设计脚本 |
| 稳定缺陷 | 最小复现步骤、期望结果、实际结果 | AI 可以先尝试复现，但不能猜正确结果 |
| 偶发或生产问题 | 脱敏日志、时间窗口、版本、环境和关联标识 | 证据不足时转为取证，不直接猜测修复 |
| 陌生或跨模块代码 | 项目文档、定向检索结果；必要时刷新知识图谱 | 图谱必须对应当前基线，结论仍需回查源码 |
| 存在参考实现 | 参考代码或文档及其适用边界 | 不能无条件复制其他项目实现 |
| MOM 核心业务 | 对象、合法状态、事实所有者、异常和追溯规则 | 关键业务事实不明确时请求业务确认 |

## 向开发人员请求资料的格式

一次性列出最多必要的几项，不让开发人员自行整理 AI 能从仓库发现的内容：

```text
当前还不能开始编码，需要补充：
1. 资料：……
   原因：它会决定……
   建议来源：……
2. 资料：……

其余代码、配置和测试信息由我从工作区获取。
```

资料暂时无法取得但风险可以接受时，记录豁免人、豁免原因、影响和补验动作；不能用“先做再说”代替豁免记录。

# 复核规则

## 何时需要独立复核

以下任一情况需要一个独立只读复核者：数据库变化、公共接口或公共对象、MOM 核心事实、安全权限、性能并发、生产偶发、跨模块大范围修改或难以回退。

普通新增功能、现有功能修改和稳定缺陷可以根据影响范围决定是否启用。简单修改不启用独立复核。

独立复核与「合并前人工确认」不是同一件事：前者检查差异和证据，后者必须由开发人员在实施对话里回复 `确认结果`。

## 独立复核者能做什么

- 只返回问题和证据（写入回复或由实施代理摘录到 `review.md`）。
- 不修改业务代码，不修改测试以制造通过，不编辑 `task-state.json`。
- 尤其不得把 `plan.approved` 或 `review.humanApproved` 设为 `true`。
- 不替人决定业务规则。

只传递任务目标、已批准方案（或简单修改的范围说明）、实际差异和测试结果，不传递主代理的思考过程、自我评价或“我认为没问题”。

## 如何选择复核方式

按当前平台选用下面的配方。若该平台做不到「不继承实施对话的只读复核」，降级为开发人员检查表，**禁止实施代理在同一对话里再看一遍自己的 diff 并勾选独立复核**。

### Cursor

1. 使用 Task / 子代理启动一个**新的只读审查者**。优先只读探索类子代理；不要用会写代码、会跑会改仓库的实现型子代理。
2. 提示词只包含：
   - 任务目录绝对路径（`.ai-sop/tasks/<task-id>/`）
   - `baseline.commit`
   - 文件级差异（`git diff <baseline.commit>`，或 `task-state.json` 的 `changes.files`）
   - 验收标准、测试记录、本文件检查表
3. 明确指令：禁止修改任何文件；禁止改 `task-state.json`；只返回发现和证据。
4. 不要粘贴实施对话全文、思维链或自我评价。
5. 子代理返回后，由实施代理把发现写入 `review.md`。无阻断问题且确实完成了这次独立复核，才把 `review.independentCompleted=true`。

### Claude Code

1. 优先用 Task / Agent 启动**隔离的只读子代理**（只给读文件、搜索类能力，不要给 Edit / Write / 会改仓库的 Bash）。
2. 若无法隔离子代理：新开一个 Claude Code 会话，**不要 resume 本实施会话**。只粘贴任务目录、基线 commit、diff 和检查表。
3. 同样禁止改代码、禁止写 `humanApproved`。只回收复结论。
4. 做不到上述任何一种时，交给开发人员按检查表执行。

### Codex

1. **新建**一个 Codex 任务或线程，不要在同一实施线程里自评。
2. 只提供 `.ai-sop/tasks/<task-id>/` 与 `git diff <baseline.commit>`（或 `changes.files`），不要带实施过程的思路。
3. 使用 `$winin-dev-sop` 并写明：本任务仅为独立只读复核，不实施、不改代码、不改确认字段。
4. 若无法新开任务，降级为开发人员检查表。

### 开发人员检查表（降级）

当平台无法提供独立上下文时，把下面检查表交给开发人员或另一名评审人员执行。实施代理可以整理 diff 和命令，但不能代替勾选，也不能因此把这次复核写成“AI 已自查”。

## 检查表

- 实际差异是否超出批准范围。
- 每条验收标准是否有真实验证证据。
- 是否存在遗漏调用方、兼容、权限、数据或回退问题。
- 测试是否验证业务结果，是否出现删除测试或放宽断言。
- 未执行项和剩余风险是否如实记录。

## 人工确认

合并前始终由**当前对话中的开发人员**确认一次，不能由实施代理或独立复核者代填。

AI 必须先完整展示：目标、文件级差异、验收标准结果、测试命令与结果、未执行项、剩余风险、下一步。展示后请开发人员回复 **`确认结果`**。

仅回复 `ok` / `好的` / `可以`，且未看到上述内容，不是有效最终确认。非简单修改的方案确认用语是 **`确认方案`**。

确认记录写入 `task-state.json`：`review.humanApproved`、`approvedBy`（开发人员）、`approvedAt`、`confirmationPhrase`（原话）、`shownToHuman`（已展示摘要）。没有人的回复就保持 `humanApproved=false`。

# 交付审查

## 适用场景

- 任务交付前的最终检查（L2 必做）。
- 独立复核：`independentReview` 任务由独立只读上下文执行本 skill 的检查表。
- 评审他人提交的代码。

纪律：只读审查，不修改任何文件。

## 执行步骤

### 1. 获取差异

```bash
git status --porcelain          # 变更文件清单
git diff --stat                 # 变更规模
git diff <baseline>             # 完整差异（单仓库基线：task-state.json baseline.commit）
git diff --name-only <baseline> # 文件清单
```

多仓库工作区（`baseline.repos` 非空）：按任务涉及仓库逐个执行 `git diff <commit>`（涉及仓库从 design.md 文件清单判断；任务不涉及的仓库跳过，不扫描）。

先核对变更文件是否超出批准范围：混入其他任务、无关重构、未确认的公共对象修改 → 立即标出。

### 2. 影响面分析（逐文件）

对每个变更文件回答：

| 维度 | 检查内容 |
| --- | --- |
| 调用方 | 谁调用这个接口/方法/组件？`rg "方法名|路径"` 全仓搜索，遗漏调用方=漏回归 |
| 接口契约 | 请求/响应字段增删改是否破坏旧调用方；DTO/实体/枚举是否公共对象 |
| 数据 | 表结构、SQL、索引、数据迁移；只读还是写；影响行数；**对历史数据的影响** |
| 权限 | 新接口是否鉴权；低权限/跨租户/未登录路径 |
| 兼容 | 序列化、消息、文件消费者、旧配置兼容 |
| 回退 | 变更能否安全回退；回退步骤 |

### 3. prd 与实际改动逐条比对

对照 `prd.md`（任务契约）与实际 git diff，逐条核对：

| prd 项 | 核对内容 |
| --- | --- |
| 目标 | 改动是否达成任务目标，有无遗漏需求 |
| 验收标准 | 每条 AC 是否有对应修改支撑；review.md「验证记录」段是否覆盖每条已勾选 AC（验证方式/结果/证据位置，无 failed，skipped 已说明原因）。机械门禁之外，核对证据是否可重复验证（测试命令/日志/截图，而非“看起来对”） |
| 范围外 | 是否越界（改了声明不做的东西） |
| 待确认项 | 编码前是否已清零（方案确认时逐条裁决或豁免） |
| 关键事实 | 改动与记录的业务规则口径是否一致 |

任务或项目规范规定了动作检查清单（如团队 T1-T10 这类逐项人工检查动作）时，逐项核对：是否已执行、完成证据在哪（文件/记录/确认人）。未定义动作清单 → 注明"本任务未定义动作清单，跳过"，不编造。

### 4. 质量与证据检查

- 逻辑：需求实现是否有错误逻辑；边界与异常路径（空值、非法输入、并发、失败分支）是否处理。
- 代码卫生：无关修改、调试代码、硬编码、TODO、吞异常、跳过或降级的测试。
- 证据真实性：验证是否通过删除正确检查、降低断言、跳过必要构建制造通过结果。

### 5. spec 合规检查

调用 `../winin-sop-spec/SKILL.md` 发现并加载命中规范，逐条核对变更是否违反（数据库规范、接口兼容规范、安全规范等）。违反项标为必须修复或人工豁免。

### 6. 输出问题清单

```text
## 差异范围
变更 5 个文件，新增 120 行 / 删除 30 行，超出批准范围：无

## 影响面
- XxxService.java: 调用方 3 处（YyyService、ZzzJob、wms-api），均已回归
- DTO 新增 2 字段，向后兼容，无旧调用方受影响；历史数据无需迁移

## prd 比对结果
- 目标: 达成（对应改动见 diff）
- AC 1/2/3: 有改动支撑 + 验证记录完整（passed）；AC 4: 验证记录 skipped 无原因 ← 需补充
- 范围外: 未越界；待确认项: 已清零；关键事实: 一致

## 规定动作核对
- 任务定义了动作清单（T1-T10），命中 T3/T7：T3 已执行（review.md 记录）、T7 无完成证据 ← 需补充

## 质量与卫生问题
- OrderQueryMapper.xml:120 硬编码状态值 '5'，触发条件：新状态类型扩展时漏改，影响：状态过滤失效

## 规范合规
- database.md §3 命中：变更含 SQL，已提供回滚脚本 ✓

## 无法确认项（需人工继续检查）
- AC 4 原筛选回归：无自动化回归基建，需人工在测试环境验证

## 检查范围与未检查内容
- 已检查：全部 5 个变更文件、3 条 AC、调用方搜索
- 未检查：未执行构建/测试（本审查只读静态）；前端页面实际交互
```

输出纪律：

- 每个问题必须给出文件位置 + 触发条件 + 影响；给不出触发条件的标为"待确认"。
- 无法确认项单独列出：哪些内容审查无法确认、需要人继续检查（缺证据、缺环境、缺业务决定）。
- 没有问题也要输出：明确说明检查范围与未检查内容，不允许以"无问题"三字带过。

## 独立复核模式

- 只传递：任务目标、批准方案、实际差异、验证结果。不传递主代理的思考过程或自我评价。
- 只返回问题和证据，不修改代码，不替人决定业务规则。
- 检查表：差异是否超范围、prd 逐条比对证据是否真实、质量与卫生问题、遗漏调用方/兼容/权限/回退、验证是否删改断言、无法确认项是否如实列出。

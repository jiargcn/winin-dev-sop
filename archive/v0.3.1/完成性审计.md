# 公司 AI 协作开发 SOP 完成性审计

审计日期：2026年8月6日。当前候选版本：`0.3.1`。

本审计以“创建一个以公司级 Skill 为入口、以独立 Sidecar 为过程监督、以项目准备卡为事实来源、以脚本和 CI 为确定性门禁的 AI 协作开发 SOP 系统”为完整目标，不以文件存在或单次测试通过代替真实可用性证明。

## 1. 逐项结论

| 目标要求 | 权威证据 | 当前结论 | 尚缺证据 |
| --- | --- | --- | --- |
| 公司级 Skill 统一入口 | `skills/company-ai-development/SKILL.md`、`agents/openai.yaml`、仓库级安装测试、项目 `AGENTS.md` 自动路由测试 | 已证明候选包结构、触发入口和仓库安装可用 | 公司受管分发渠道和升级策略需在试点后确定 |
| 直观自动选路 | 七类场景、路由规则、五个独立上下文前向任务和一个真实 A2 示例 | 已证明代表性任务可唯一选路，并能在业务含义不清时停止猜测 | 真实任务单的总体误判率尚未统计 |
| 每类场景可直接执行 | 七张独立场景卡，每张包含流程图、步骤、人只需确认、完成证据和样例 | 文档结构已证明完整 | 尚未观察普通开发人员是否无需作者解释即可执行 |
| 项目准备卡作为事实来源 | 自动草拟脚本、JSON Schema、验证器、Maven/Vue 草拟测试和 `win-module-label` 真实准备卡 | 已证明单模块 Java/Vue 真实仓库的路径和四组命令可用，并据试点补齐中文契约识别 | 真实多模块仓库和 DDL 任务仍未证明 |
| 独立 Sidecar 监督 | 独立上下文协议、计划和最终检查包、结构化报告、哈希验证、模拟反例和真实 A2 方案两轮复核 | 已证明实际 AI 环境能够只读阻断并在修订后放行；首次执行存在等待重试 | 仍需统计长期成功率和平均耗时 |
| 证据不能被手工 `pass` 绕过 | 报告 Schema、任务状态绑定、场景一致性、增强动作证据、仓库内容快照和过期报告反例 | 已证明 | 不把该机制当成恶意人员防篡改安全系统；其目标是防止误操作和 AI 自我宣告完成 |
| 脚本确定性门禁 | 12 个 PowerShell 脚本和 45 项自动化断言 | 已证明 Windows 试验环境通过，并在含中文路径、脏工作区和真实仓库中暴露并修复问题 | 大型仓库长期运行耗时尚未证明 |
| GitHub Actions 门禁 | 工作流模板、YAML 解析、不同路径全新 Git checkout 的通过与失败验证 | 已证明 CI 等价脚本逻辑 | 尚无真实 GitHub Pull Request 的 Actions 运行记录 |
| 降低开发人员流程负担 | 自动入口、自动选路、自动准备卡草拟、按需只加载一张 SOP、一页操作卡和真实任务最小澄清 | 真实示例中开发人员只需回答业务含义，不需要手选场景或操作脚本 | 尚无三名不同 AI 熟练度开发人员的对照数据 |

## 2. 已完成的验证

当前自动化测试执行45项断言，覆盖初始化、准备卡草拟、中文契约识别、Schema、自动入口、任务生命周期、取消交接、选路门禁、附加动作、脏工作区文件清单、Sidecar 双基准路径、证据锚点、仓库快照、换目录验证、过期失效、安装和 UI 元数据。Skill 官方结构验证通过，12个 PowerShell 脚本语法解析通过，JSON、YAML、Markdown、链接、代码围栏、七张流程图和七个场景样例检查通过。

代表性前向测试已覆盖 A3 展示修改、A2 现有逻辑修改、稳定缺陷、生产偶发缺陷和依赖升级。独立 Sidecar 已阻断时区口径缺失、破坏索引的查询、回归测试遗漏、漏跑项目规定命令，以及“完成摘要与实际差异不一致”的虚假完成样例。

## 3. 当前发布判定

当前版本可以标记为“经一次真实项目验证的扩大试点候选版”，不能标记为“公司稳定版”或“全面推广完成”。真实项目已经证明准备卡、真实 Maven/Vitest、自动选路、最小澄清、计划 Sidecar 和门禁能够工作；以下要求仍没有当前证据：

1. 至少一项真实 A2 需求或 B 类缺陷从任务接管走到 `ready_for_review`；本次按实验约定在业务编码前停止。
2. 至少一次真实 GitHub Pull Request 中，完整证据通过 Actions，缺失或过期证据能够失败。
3. 至少三名 AI 使用经验不同的开发人员完成试用，并记录人工提问数、无关修改、测试遗漏、返工次数和主观负担。
4. 至少一个真实多模块或 DDL 任务验证准备卡、数据增强动作和回退证据。

## 4. 下一轮试点重点

下一轮不应继续扩写规范，而应选择一项允许真正提交评审的局部 A2 或稳定缺陷，完成编码、最终 Sidecar 和 Pull Request Actions；同时由三名不同 AI 熟练度的开发人员分别试用一项任务。只有这些数据表明流程操作和返工确实下降，才考虑稳定版编号。

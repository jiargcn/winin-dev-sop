# 公司 AI 协作开发 SOP 前向测试报告

## 1. 测试方式

测试日期为 2026年8月5日至6日。模拟场景测试使用独立代理上下文，只提供 Skill 路径和原始任务描述，不提供预期分类、设计结论或当前对话历史。真实项目试点使用独立 Sidecar，只提供不可变检查包，明确禁止修改文件。

## 2. 自动化脚本测试

`Test-AiSopScripts.ps1` 在临时 Git 仓库中执行45项断言，覆盖：

- 项目准备卡、Schema、验证器和 GitHub Actions 初始化；
- 项目 `AGENTS.md` 自动路由开发任务到公司 Skill；
- 未配置准备卡被阻断、已验证准备卡通过；
- 准备卡能够从 Maven 与 Vue 项目结构自动草拟后端、前端测试和构建命令；
- 准备卡能够识别中文命名的接口契约文档；
- 任务状态初始化和 JSON Schema；
- Sidecar 检查包、报告 Schema、输入哈希和独立报告验证；
- 仅在任务状态中声称“可实施”而没有有效 Sidecar 证据时，实施门禁拒绝放行；
- Sidecar 默认拒绝读取项目根目录和批准证据目录之外的文件；
- 不完整任务路由被阻断；
- 路由、实施和评审三个门禁的通过路径；
- 数据库变化、MOM核心事实变化、并发和偶发问题信号；
- 完成报告生成；
- Sidecar 检查后的 diff 发生变化时，旧报告自动失效；
- Sidecar 证据使用可迁移的包相对路径，并能在另一个目录的全新 Git checkout 中重新通过评审门禁；
- Sidecar 参数同时接受任务状态目录相对路径和项目根目录下的 `.ai-sop/...` 路径，门禁能够识别标题锚点；
- Sidecar 最终检查后仓库代码或文件集合发生变化时，评审门禁自动失效；
- 同一分支中的活动任务不能被新任务覆盖，已达到 `ready_for_review` 的任务可以自动交接给下一任务；
- 被撤回或仅作实验的 `cancelled` 任务不能通过交付门禁，但允许自动交接下一任务；
- 同时存在一个已修改文件和多个未跟踪文件时，信号脚本保持文件清单逐项独立；
- 命中 MOM、数据库、接口、安全、性能等附加情况后，对应增强动作没有完成证据时实施门禁拒绝放行；
- 高风险任务不能使用人工快速 Sidecar 兜底，Sidecar 报告场景必须与当前任务一致；
- 仓库范围 Skill 安装和 UI 元数据。

测试结果为45项全部通过。Skill 官方结构校验通过，所有 PowerShell 脚本语法解析无错误。

## 3. 场景选路测试

| 原始任务 | 实际选路 | 结果 |
| --- | --- | --- |
| Vue 3 页面字段标题修改，明确不改变绑定、接口和业务含义 | A3 展示性修改 | 正确；排除了否定句中的接口、权限等候选信号 |
| MES 工单列表增加产线和计划日期组合筛选 | A2 现有功能修改 | 正确；识别出时区口径是编码前最少人工决定 |
| 同一工序重复投料同一唯一码，能够稳定复现 | B 可稳定复现缺陷 | 正确；要求修复前失败、修复后通过和并发验证 |
| 生产偶发重复报工，测试环境无法复现 | C 难复现缺陷 | 正确；阻止猜测式改码，要求先取证和观察状态 |
| PostgreSQL JDBC 驱动漏洞修复，业务行为保持不变 | D 工程变更 | 正确；只确认安全依赖信号，排除数据库结构和契约变化 |

五个任务均在没有人工选择场景的情况下得到唯一主场景。测试发现关键词脚本会把任务中的否定描述识别成候选信号，因此机器信号被明确设计为候选，必须由 Skill 结合否定语义和项目证据确认后才能写入正式任务状态。

## 4. Sidecar 计划检查

第一版评测方案使用服务器默认时区、对时间列执行 `DATE()`、只设计一个组合筛选测试，并省略回退。独立 Sidecar 返回阻断，识别出以下问题：

- 日期业务时区没有权威依据；
- 日期查询可能破坏索引使用；
- 单独筛选、边界和原筛选回归未覆盖；
- 新接口参数的契约不完整。

补充业务规则、半开时间范围、单列和组合索引、接口契约、明确验收数据、性能基线和回退后，第二次 Sidecar 仍发现遗漏项目准备卡规定的 `mvn verify`。补充该命令后，第三个全新 Sidecar 返回 `pass`，没有遗留问题或缺失证据。

这证明项目准备卡能够作为事实来源约束实际方案，Sidecar 不会因为方案文字看起来完整就直接放行。

## 5. Sidecar 最终检查反例

最终检查评测提供了一份声称所有测试通过的测试报告，但实际 diff 中只有注释形式的空测试、缺少产线后端条件和非法日期处理，OpenAPI 差异也没有包含完整契约。独立 Sidecar 返回 `block`，并准确指出测试报告无法被原始差异支持。

该结果证明 Sidecar 会交叉验证任务状态、原始差异、契约和测试证据，而不是把开发代理生成的完成摘要当成事实。

## 6. 本轮修正

前向测试后完成以下修正：

1. 将机器状态中的风险名称改为 `databaseChange`、`contractChange`、`momCoreChange` 和 `performanceRisk`，避免普通查询或普通 MOM 页面自动触发重流程。
2. 在 Sidecar 协议中明确数据库变化、契约变化和 MOM 核心事实变化的边界。
3. 项目准备卡增加独立验证器和 JSON Schema。
4. GitHub Actions 同时检查项目准备卡和任务完成状态。
5. 自动测试增加项目准备卡失败/成功、Schema 和仓库范围安装验证。
6. Sidecar 报告改为绑定不可变检查包及其输入文件 SHA-256，任务状态中的手工 `pass` 不再构成放行证据。
7. 真实项目试点后修复单个 Git diff 文件与多个状态文件被拼接的问题，并增加回归测试。
8. 准备卡补充中文“接口契约文档”自动识别；Sidecar 路径同时兼容状态目录和项目根目录写法。
9. 明确“先稳定任务状态、再生成检查包、门禁前不再改状态”的顺序，避免通过报告因登记状态而立即过期。
10. 增加 `cancelled` 终态，使撤回任务和实验样例能够无删除地结束并交接下一任务。

## 7. 真实项目试点

2026年8月6日在一个真实的 Java/Vue 示例项目仓库中进行了不进入业务编码的流程实验。仓库级 Skill、`.ai-sop`、受管 `AGENTS.md` 和 GitHub Actions 模板均成功初始化；准备卡正确识别 Java 17、Spring Boot 3、Maven、Vue 3、npm 和主分支，真实执行后端测试、后端 `verify`、前端 Vitest 和前端生产构建全部通过。后端基线为160项测试、0失败、0错误、6跳过，前端为185项测试全部通过。

示例任务“固定分隔符支持一级、二级、三级分隔符自定义”被自动选为 A2，并识别为契约变化。Skill 没有猜测层级含义，而是提出一个最小业务问题；任务提出人给出并修正示例后，流程形成新旧契约、兼容策略、回退和测试矩阵。第一轮计划 Sidecar 阻断了旧规则隐式升级、后端校验责任和数组长度语义三个缺口；修订后第二轮返回 `pass`。业务代码按实验约定未实施。

试点同时证明确定性门禁确实会阻止错误的证据路径、缺少集成批准和审查后继续修改任务状态。上述问题已经回灌脚本、协议和回归测试。尚未验证的内容缩小为：Understand Anything 在大型陌生仓库中的实际耗时、完整业务实现到最终 Sidecar、真实 GitHub Pull Request Actions，以及不同 AI 熟练度开发人员的主观负担。

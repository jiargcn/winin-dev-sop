# MOM 领域检查清单

## 1. 使用方式

任务命中 `MOM-DOMAIN` 时，开发人员在方案、测试和自测中按实际业务域应用本清单。清单提供通用离散制造基线，不代表某个项目现状；项目资料和已确认规则优先。

## 2. 业务闭环

使用“来源或订单—申请或计划—可执行任务—现场执行—业务记录—领域结果—事件或接口—查询与追溯”检查链路。对象不一定采用这些名称，但必须明确业务意图、执行和已发生事实之间的区别。

至少回答：谁提出、谁接受或批准、谁执行、谁确认结果；哪些状态可以推进、撤销、关闭、冲销、返工或补偿；失败后如何恢复；来源能否正向核对结果，结果能否反向追溯来源。

## 3. 事实所有权

| 领域 | 默认权威事实 | 不应默认承担 |
| --- | --- | --- |
| MES | 工单执行、工序作业、投料、报工和生产履历 | 库存余额、检验结论、维修工单 |
| WMS | 仓储任务与记录、库存预期、事务、余额和盘点结果 | 生产报工、检验判定、财务事实 |
| QMS | 检验方案、任务、记录、判定、评审和质量通知 | 实际库存移动和生产报工 |
| EAM | 维修、巡检、保养、停机和维护履历 | 库存余额、设备实时控制、ANDON 到岗过程 |
| ANDON | 异常事件、呼叫、响应、升级和到岗过程 | 维修完成、检验结论和生产报工 |
| SCP | 经确认的跨企业发布、反馈、差异、协商和单据流转 | ERP 正式记账、WMS 库存和 QMS 检验 |
| 追溯投影 | 跨域查询索引和关系视图 | 替代各业务域写入权 |

项目可以调整默认边界，但必须记录依据。两个系统可能写同一事实时，先明确主从、冲突、门禁和对账，不用“双向同步”回避决策。

## 4. 对象与状态

- 区分订单与工单、申请与任务、执行记录与结果。
- 区分库存预期、库存事务与库存余额。
- 区分质量判定与 WMS 实际库存处置。
- 区分批次、波次、唯一码和容器，不因名称相近合并语义。
- 状态变化应有合法来源、操作者、时间、原因和审计；禁止直接修改结果状态绕过业务动作。
- PDA、线边端、门户和大屏是执行或展示终端，不是独立事实域。

## 5. 异常、一致性与追溯

跨域调用需定义成功确认、超时、重试、幂等、重复、乱序、部分成功、补偿和对账。高风险库存过账、质量放行和身份变更优先使用明确业务门禁；跨域查询可使用异步投影，但必须说明数据新鲜度。

异常处理不能只恢复技术调用，还应回答业务对象最终处于什么状态、是否允许继续执行、如何人工介入以及历史链是否完整。更正、冲销和补偿应保留原事实及关联关系。

## 6. 测试要求

除正常流程外，至少测试非法状态跳转、重复操作、并发、撤销、冲销、返工、补偿、跨域失败、权限、历史数据和正反向追溯。涉及库存时对账事务与余额，涉及质量时核对判定与处置，涉及设备与 ANDON 时区分响应结束和维修完成。

# ENG-05：DDL、数据迁移和修复脚本

## 1. 适用条件、反例和选择规则

本流程适用于已确认规则下的 PostgreSQL DDL、数据迁移、初始化、历史修复或补偿脚本。尚未确认数据异常根因和正确值时使用 `BUG-05`；以新增业务能力为主时使用需求流程并叠加 `DATA`。

本场景固定为 `L3` 和 `DATA`。开发流程只交付经过验证的脚本及执行前提，不等于授权或完成生产执行。

## 2. 必要输入、缺失处理和开始条件

取得目标环境 schema 版本、最新 DDL、迁移历史、数据规则、权威来源、影响范围、数据规模、维护窗口、备份能力和执行责任人。缺少任何会影响筛选、计算、锁或回退的事实时停止。

## 3. 任务澄清、验收标准和范围

明确变更对象、迁移前后结构或数据、适用环境、是否在线执行、可接受锁时间、失败处理和对账口径。验收必须量化预计与实际行数、约束和索引状态、业务不变量及回退可行性。

## 4. 项目与代码上下文准备

从受控来源取得最新 PostgreSQL DDL、迁移脚本、索引、约束、触发器、视图、序列和应用映射。确认目标分支、应用版本和数据库版本匹配。使用只读查询分析数据分布，生产结果必须脱敏后才能进入 AI。

## 5. 现状、影响和证据分析

检查所有读写目标表、字段或对象的代码、任务、接口和报表。计算影响行数、数据分布、异常边界、依赖对象、锁类型、磁盘与 WAL 影响。MOM 数据必须确认事实所有权和合法纠正动作，不直接覆盖应通过冲销或补偿形成的业务历史。

## 6. 开发方案设计

方案包含前置检查、只读预览、DDL/数据脚本、事务或分批策略、幂等、断点续跑、锁与超时、备份、回退、执行后对账和应用兼容顺序。结构变化优先使用向前兼容的扩展—迁移—切换—清理路径。

所有脚本和回退方案在主体执行前人工评审。不可逆变化必须说明为什么无法回退以及可采用的恢复方式。

## 7. 专用测试用例设计

至少覆盖：

- 空库、标准数据、边界数据、脏数据和大数据量。
- 零命中、单条、批量、中断、重跑和重复执行。
- 新旧应用版本与 schema 的兼容窗口。
- 约束、索引、序列、默认值和 NULL 行为。
- 锁等待、超时、事务回滚和分批恢复。
- 预计/实际行数、前后数据、业务不变量和跨表/跨系统对账。

## 8. 分步编码与每轮验证

先编写独立只读预览和前置检查，再编写正式脚本及回退。使用隔离副本或代表性测试库试运行，记录执行计划、耗时、锁和结果。脚本不得依赖人工临时修改中间数据才能成功。

## 9. AI 差异审查、人工检查和风险复核

AI 可检查 SQL 语义、NULL、重复、连接条件、幂等、锁和性能风险，但开发人员必须使用 PostgreSQL 实际执行计划和独立对账查询验证。不得向外部 AI 提交真实生产明细、连接信息或备份内容。

## 10. 自测、结果记录和完成条件

在代表性环境执行前置检查、试运行、正式路径、重复执行、中断恢复、回退和对账。相关应用执行 `mvn test`/`mvn verify`，GitHub Actions 通过。记录脚本校验和、环境 schema 版本、预计/实际行数、耗时和结果。

## 11. 必须保留的最终产物

- 最新 DDL 与目标版本依据、影响分析和开发方案。
- 前置检查、预览、正式、对账和回退脚本。
- 人工评审及试运行报告。
- 执行顺序、授权前提、监控项和剩余风险。

## 12. 停止、升级或评审条件

DDL 版本不一致、数据规则或权威来源不清、影响范围不可计算、没有备份/恢复或无法控制锁影响时停止。生产执行另走项目授权和发布流程，不因开发自测通过自动获得权限。

## 13. 禁止事项

禁止无条件全表更新或删除；禁止没有只读预览直接执行；禁止省略幂等、备份、回退和独立对账；禁止使用未验证的生产表名或字段；禁止覆盖应保留的业务历史；禁止将生产凭据写入脚本。

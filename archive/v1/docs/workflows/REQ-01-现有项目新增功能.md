# REQ-01：现有项目新增独立功能或业务能力

## 1. 适用条件、反例和选择规则

本流程适用于在现有项目中增加此前不存在、可以独立验收的业务能力，例如新增一种业务单据、作业任务、查询能力或外部协同入口。只是改变既有流程规则时使用 `REQ-02`；仅改善页面操作时使用 `REQ-03`；主要工作是适配外部契约时使用 `ENG-03`。

默认风险等级为 `L2`。涉及 DDL、公共接口、权限、MOM 核心事实或跨服务时升级为 `L3`，主体编码前必须完成人工开发方案评审。

## 2. 必要输入、缺失处理和开始条件

开始前应取得任务单、业务提出人、目标用户、场景、验收标准、目标版本、代码基线和项目 AI 数据规则。还应取得相关模块说明、现有相近功能、最新 PostgreSQL DDL、接口契约和可用测试。

如果新增能力的业务价值、核心角色、业务结果或事实所有权不清楚，应先确认，不得由 AI 根据相似代码补造需求。只缺少实现细节时，可以形成带验证方法的假设。

## 3. 任务澄清、验收标准和范围

把任务拆成触发条件、参与角色、主流程、异常流程、最终结果和可观察验收。明确本次新增哪些业务对象、状态、权限、页面、接口、数据和日志，同时列出明确不建设的相邻能力。验收标准必须覆盖正常完成、拒绝或失败、重复操作、撤销或补偿以及权限差异。

## 4. 项目与代码上下文准备

确认正确仓库、基线提交和干净工作区，运行现有构建与相关测试。首次接触大型项目、新增模块、跨模块或文档薄弱时，使用 `$understand --language zh` 构建或刷新知识图谱，并确认图谱的提交哈希与基线一致；局部功能可用定向检索、调用链和相近测试分析。

涉及数据库时获取目标环境对应的最新 DDL、迁移记录、约束和索引；涉及接口时收集调用方、契约、错误码和样例；涉及 MOM 时梳理“来源或订单—任务—执行—记录—领域结果—接口或事件—查询追溯”的完整链路。

## 5. 现状、影响和证据分析

列出现有相近能力可以复用的业务规则、组件和测试，并区分可复用事实与仅供参考的实现。沿入口、服务、领域对象、数据库、接口、前端和权限追踪影响链，确认新增能力不会错误复用其他领域的权威数据。

证据至少包括代码位置、DDL 或迁移版本、接口版本、相关测试和已确认业务规则。AI 推断必须单独列出并验证。

## 6. 开发方案设计

开发方案应描述目标行为、业务流程、对象与状态、模块职责、数据和接口变化、权限、异常恢复、兼容、可观测性及回退。命中 `MOM-DOMAIN` 时，明确事实创建方、修改方、权威存储、引用方和查询投影，并覆盖撤销、冲销、返工、补偿和追溯。

优先沿现有架构扩展，确需引入新模式时说明原方案为何不满足、替代选项和长期维护影响。`L3` 方案评审通过后再开始主体编码。

## 7. 专用测试用例设计

至少设计以下用例：

- 核心业务从合法输入走到领域结果的正常路径。
- 必填、边界值、重复提交、非法状态和无权限操作。
- 依赖失败、部分成功、重试、撤销、冲销或补偿。
- 历史数据和相关既有功能的回归。
- API、消息或数据变更的兼容、幂等和重复消费。
- Vue 页面加载、空态、错误态、按钮状态和重复点击。

自动化测试薄弱时，先为复用的关键旧行为补特征测试，再为新能力补 JUnit 5/Mockito 和 Vitest 测试。

## 8. 分步编码与每轮验证

按“领域规则和测试—后端实现—数据库或接口—前端交互—集成验证”的可验证切片推进。每个切片只引入当前能力所需改动，并运行最近层级测试。不得顺带重构无关模块或升级依赖。

## 9. AI 差异审查、人工检查和风险复核

向 AI 提供任务目标、验收标准、风险标签、方案和最终差异，要求检查遗漏行为、异常路径、权限、兼容、并发、测试缺口和无关改动。开发人员逐文件核对结论，并重新确认实施中是否新增了 `DATA`、`CONTRACT`、`SECURITY` 或 `CROSS-MODULE` 风险。

## 10. 自测、结果记录和完成条件

执行相关模块的 `mvn test`，适用时执行 `mvn verify`；前端执行 `npm run test` 和 `npm run build`。完成主要业务流程、异常、权限、数据结果和回归验证，并确认 GitHub Actions 通过。未执行项必须记录原因、影响和后续责任。

## 11. 必须保留的最终产物

- `L2/L3` 开发方案及评审结论。
- 正式代码、测试代码、DDL/接口契约等变更。
- 自测报告和 Pull Request 影响摘要。
- 未验证假设、已知限制和剩余风险。

## 12. 停止、升级或评审条件

业务对象、状态、系统边界、数据所有权或验收标准存在冲突时停止编码。命中高风险标签、方案扩大到跨服务或出现难以回退的数据影响时升级为 `L3` 并发起评审。

## 13. 禁止事项

禁止把相似页面当成完整需求证据；禁止先生成大批代码再补方案和测试；禁止为方便查询改变事实所有权；禁止隐藏无法实现的异常路径；禁止以 AI 审查替代人工差异检查和确定性测试。

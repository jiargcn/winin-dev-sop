# BUG-07：权限、安全与敏感信息缺陷

## 1. 适用条件、反例和选择规则

本流程适用于认证绕过、越权、跨租户访问、注入、依赖漏洞、密钥泄露、日志或接口暴露敏感信息等问题。普通功能权限需求变更仍可使用 `REQ-02`，但必须叠加 `SECURITY`。

本场景固定为 `L3` 和 `SECURITY`。信息披露范围遵循最小知情原则，不在普通任务评论中复制利用细节、密钥或真实敏感数据。

## 2. 必要输入、缺失处理和开始条件

取得受影响版本、入口、角色或攻击前提、影响对象、发现证据和允许的验证环境。立即判断是否需要撤销凭据、关闭入口或通知安全/项目负责人。生产验证必须获得授权。

## 3. 任务澄清、验收标准和范围

明确安全边界、攻击者能力、受影响资产、影响版本和止损目标。验收标准应证明原攻击路径被阻断、合法用户功能不受影响、相关变体已检查，泄露的凭据或数据已经按组织流程处置。

## 4. 项目与代码上下文准备

在隔离分支和授权环境分析认证链、授权检查、租户条件、输入处理、序列化、文件访问、依赖和日志。跨模块时刷新知识图谱，但不得把漏洞细节或敏感样例提交给未授权 AI。固定依赖锁定文件和构建产物版本。

## 5. 现状、影响和证据分析

建立从入口到受保护资源的完整信任边界，区分认证、功能权限、数据权限和租户隔离。确认所有等价入口和批量接口，评估是否已经被利用。依赖漏洞需核对实际可达性、官方公告和受影响版本，不仅依据扫描器标题。

## 6. 开发方案设计

优先在权威服务端实施最小权限和集中校验，不把前端隐藏当成安全控制。方案包含止损、永久修复、凭据轮换、日志脱敏、兼容、审计和回退。人工评审确认修复不会形成新的绕过路径。

## 7. 专用测试用例设计

至少覆盖：

- 未认证、低权限、高权限、跨角色和跨租户访问。
- 修改对象标识、批量接口、导入导出和间接引用。
- 空值、编码、边界输入及适用的注入变体。
- 令牌过期、撤销、重放和会话切换。
- 日志、错误响应、导出文件和前端缓存的敏感信息。
- 合法业务路径和旧客户端兼容回归。

## 8. 分步编码与每轮验证

先建立能在授权环境证明漏洞的最小安全测试，再实施服务端修复和相关前端反馈。每一步运行安全回归，不保留可直接用于未授权攻击的测试数据或文档。凭据轮换与代码修改分开受控执行。

## 9. AI 差异审查、人工检查和风险复核

AI 只处理授权、最小化的代码和脱敏证据。要求其检查绕过路径、校验位置、默认权限、日志、依赖和测试缺口。开发人员或安全责任人复核所有建议；AI 不得决定漏洞披露范围和生产处置。

## 10. 自测、结果记录和完成条件

执行安全回归、相关 `mvn test`、`mvn verify`、前端测试和构建、依赖与静态安全检查，并确认 GitHub Actions 通过。记录原路径被阻断、合法路径正常和相关变体结果。生产凭据或数据处置状态单独标记，不因代码完成自动关闭。

## 11. 必须保留的最终产物

- 受控的漏洞描述、影响范围和风险等级。
- 修复方案、人工评审和安全测试。
- 代码、依赖、配置或脱敏变更。
- 自测、处置状态、披露边界和剩余风险。

## 12. 停止、升级或评审条件

验证可能影响生产、扩大数据暴露、需要访问真实密钥或发现正在被利用时立即停止普通流程并升级安全/项目负责人。不得自行开展超出授权范围的探测。

## 13. 禁止事项

禁止向未授权 AI 输入漏洞利用细节、密钥或真实数据；禁止用前端控制代替服务端授权；禁止仅修一个入口；禁止把扫描器告警未经验证写成已确认漏洞；禁止在公开 Pull Request 描述中泄露利用方法。
